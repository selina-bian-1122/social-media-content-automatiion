# OrphLux 社媒内容自动化

以飞书多维表格为中枢的海外社媒（X 起步）内容流水线：**素材收集 → AI 筛选选题 → 人工采纳 → AI 写初稿 → 人工定稿发布**。
AI 负责"找素材、判相关性、写初稿"，人负责"选题、定稿、审核、发布"——所有人工决策都在表格里完成。

```
 ① RSS 自动抓取 ─┐
                 ├─▶【素材收集】──② AI 判断相关性──▶【选题库】──③ 人工采纳 + 选账号──▶ ④ AI 写初稿 ──▶【内容库】──⑤ 人工定稿 / 审核 / 发布
 ①½ 人工提报 ────┘      (待处理)                     (待筛选)       (已采纳)                          (待人工编辑)
```

---

## 使用指南：我该做什么？

大部分人**只需要打开飞书多维表格**，不用碰代码。按你的角色看对应部分即可。

### 👀 所有人：提报素材

看到值得发的内容（文章、新闻、客户案例、内部观点）：

1. 打开【素材收集】表，点「+ 新增记录」
2. 填「原文链接」；没有链接就在「素材描述」里写一段文字
3. 「来源」选"人工提报"，「处理状态」选"待处理"（留空也可以）

之后 AI 会自动判断它是否值得做成选题，人工提报的素材会被优先处理。

### ✅ 选题负责人：筛选选题

1. 打开【选题库】，筛选「状态 = 待筛选」
2. 看每条的「AI摘要」「建议角度」「优先级」，决定做不做
3. **要做的**：先在「适配账号」里选用哪些账号发（按账号人设匹配），**再**把「状态」改为「已采纳」
4. **不做的**：「状态」改为「已淘汰」

> ⚠️ 一定要先选「适配账号」再改「已采纳」，否则不会生成初稿。

几分钟后（取决于脚本运行频率），【内容库】会出现对应的 AI 初稿。

### ✍️ 编辑：把初稿改成定稿

1. 打开【内容库】，筛选「状态 = 待人工编辑」
2. 参考「AI初稿」，在「定稿文案」里写最终版本（AI 初稿末尾的 Notes 会提示需要核实的事实）
3. 改完把「状态」改为「待审核」

### 🔍 审核人：审核与发布

1. 【内容库】筛选「状态 = 待审核」，审阅「定稿文案」
2. **通过**：「状态」改为「已通过」→ 在 X 上发布 → 回填「发布链接」「实际发布时间」（也可以决定不发布）
3. **不通过**：在「驳回原因」写明问题，「状态」改回「待人工编辑」

### ⚙️ 运营同学：让流水线跑起来

只需要一个人在自己电脑上运行脚本（首次配置见下方「快速开始」）。最省事的方式是让它常驻、每分钟自动跑一轮：

```bash
python main.py --interval 1
```

它会自动完成：抓 RSS → AI 把素材筛成选题 → 为已采纳的选题写初稿。其他人只需要在表格里按上面的步骤操作。
想手动一步步控制，见下方「端到端工作流」。

## 快速开始（首次配置，只需运营同学做一次）

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 配置 `.env`

```bash
cp .env.example .env
```

| 配置项 | 说明 |
|---|---|
| `LARK_APP_ID` / `LARK_APP_SECRET` | 飞书开放平台自建应用凭证 |
| `LARK_BASE_APP_TOKEN` / `LARK_TABLE_*` | 多维表格 app_token 与各表 table_id（浏览器地址栏可见） |
| `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` | AI 密钥，`AI_PROVIDER` 选择使用哪个 |
| `ANTHROPIC_BASE_URL` / `OPENAI_BASE_URL` | 使用第三方中转服务时填接口地址（OpenAI 格式通常需以 `/v1` 结尾）；留空直连官方 |
| `AI_MODEL` | 模型名，如 `claude-sonnet-4-6` |
| `RSS_MAX_PER_FEED` / `RSS_MAX_AGE_DAYS` | 每个 RSS 源只看最新 N 条 / 只收 N 天内文章（默认 5 / 3） |
| `LARK_BOT_CHAT_ID`、`BOT_*` | 飞书 bot 相关，可选，见下文「飞书 Bot」 |

> `.env` 以文件内容为准（会覆盖终端里同名的环境变量），且已被 `.gitignore` 排除，**不要提交**。

### 3. 连通性检查

```bash
python test_connection.py
```

看到飞书表格读取成功、`AI API 调用成功` 即可开始。

## 飞书应用与表格要求

**应用权限**（开放平台 → 权限管理，改完需发布新版本）

| 权限 | 用途 |
|---|---|
| `bitable:app` | 读写多维表格（必需） |
| `im:message:send_as_bot` | bot 发消息（使用 bot / `--push` 时需要） |
| `im:message.group_msg` | 读取 bot 所在群的消息（群聊 bot 需要，敏感权限） |
| `contact:user.id:readonly` | 用邮箱换 open_id（`BOT_ADMIN_EMAILS` 需要） |
| `im:chat:readonly` | 查询 bot 所在群的 chat_id |

**多维表格结构**（字段名需一致）

| 表 | 关键字段 |
|---|---|
| 素材收集 | 素材描述、原文链接、来源（人工提报/RSS抓取/…）、处理状态（待处理/已转选题/已跳过）、转入选题、跳过原因 |
| 选题库 | **编号**（自动编号）、标题、AI摘要、建议角度、行业标签、优先级、**适配账号**（关联账号矩阵）、状态（待筛选/已采纳/已淘汰） |
| 账号矩阵 | **编号**（自动编号）、姓名、平台、人设定位标签、状态（启用/停用） |
| 内容库 | AI初稿、关联选题、关联账号、内容形式、定稿文案、状态、驳回原因、发布链接 等 |

> 单选字段只会写入表格中**已存在**的选项；写入不存在的值飞书会自动新建选项，所以改选项名时要同步改代码。

## 端到端工作流

### ① RSS 自动抓取

```bash
python main.py --fetch-rss
```

RSS 源在 [`config/topic_domains.yaml`](config/topic_domains.yaml)。每个源只看最新 `RSS_MAX_PER_FEED` 条、只收 `RSS_MAX_AGE_DAYS` 天内的文章，已抓过的链接自动跳过——**重复运行不会越抓越多**。

### ①½ 人工提报素材（两种方式任选）

- **表格**：在【素材收集】新增一行，填「原文链接」或只写「素材描述」；「处理状态」选"待处理"或留空均可。
- **命令行**（链接或一段文字都行，可多条）：

  ```bash
  python main.py --add "https://example.com/article" --note "可结合我们的标注质检经验"
  python main.py --add "我们刚交付了 10 万条 RLHF 标注项目，可以聊聊质检流程"
  ```

### ② AI 筛选进选题库

```bash
python main.py --process-materials
```

- 人工提报的素材**优先处理**，然后才是 RSS 素材。
- 相关的素材 → 【选题库】新增「待筛选」选题（含 AI 摘要、建议角度、优先级、行业标签），素材标记「已转选题」。
- 不相关的 → 素材标记「已跳过」并写明「跳过原因」。
- 相关性维度与阈值在 [`config/topic_domains.yaml`](config/topic_domains.yaml) 的 `domains` / `filters` 中配置。

### ③ 人工筛选（在表格里）

在【选题库】里：
1. 先选「**适配账号**」（用哪些账号发，按账号人设匹配）；
2. 再把「状态」改为「**已采纳**」；不做的改「已淘汰」。

> ⚠️ 已采纳但没填适配账号的选题会被第 ④ 步跳过（终端日志会提示）。

### ④ AI 写初稿

```bash
python main.py --generate-content
```

为每个「已采纳选题 × 适配账号」组合生成一条 X 初稿（按账号人设），写入【内容库】。已生成过的组合不会重复生成。

### ⑤ 人工定稿、审核、发布（在表格里）

【内容库】「状态」四个取值：

| 状态 | 含义 | 谁改 | 下一步 |
|---|---|---|---|
| 生成中 | AI 正在写初稿 | 脚本 | 写完自动变「待人工编辑」 |
| 待人工编辑 | AI 初稿已就绪 | 脚本 | 编辑人写「定稿文案」，改为「待审核」 |
| 待审核 | 等待审核 | 编辑人 | 通过 → 「已通过」；不通过 → 填「驳回原因」改回「待人工编辑」 |
| 已通过 | 可以发布 | 审核人 | 人工在 X 发布并填「发布链接」；也可以不发布 |

脚本只写前两个状态，之后全部由人工推进，**不会自动发布**。

### 一键 / 定时运行

```bash
python main.py --once                 # ①②④ 各跑一次
python main.py --interval 1           # 每 1 分钟自动跑 ①②④（Ctrl+C 退出）；人只需在表格里做 ③⑤
python main.py --interval 1 --skip-rss  # 同上但不抓 RSS
```

加 `--push` 会在每轮结束后把新选题卡片 / 结果推送到飞书（`LARK_BOT_CHAT_ID`）。

## 命令行快捷操作：`ops.py`（可选）

不想切到表格时，可以直接在终端完成 ③：

```bash
python ops.py status              # 各环节待办数量
python ops.py topics              # 列出待筛选选题与可用账号
python ops.py adopt T86 A1 A2     # 采纳选题 86，用账号 1、2 生成初稿（或 adopt T86 all）
python ops.py reject T79          # 淘汰选题 79
python ops.py add <URL> --note "说明"
python ops.py fetch | process | generate | run
```

**T / A 编号 = 选题库 / 账号矩阵里「编号」列的数字**（自动编号，永久不变，与视图排序无关）。

## 飞书 Bot（可选）

`bot_listener.py` 让团队在飞书里用文字指令驱动同一套流程，所有写表 / 调 AI 的操作都需先批准。

```bash
python bot_listener.py
```

| 指令 | 作用 |
|---|---|
| 发链接（可附说明） | 写入素材表，并发起「立即加工」审批 |
| `待办` | 各环节待处理数量 |
| `选题` | 推送待筛选选题卡片 |
| `采纳 T86 A1 A2` / `采纳 T86 全部` / `淘汰 T79` | 采纳（并生成初稿）/ 淘汰选题 |
| `跑一遍` / `抓取` / `加工` / `生成` | 发起审批（编号 R#） |
| `批准 R2` / `取消 R2` | 处理审批 |
| `帮助` | 查看说明 |

**两种接收模式**（`.env` 中 `BOT_MODE`）：

- `poll`（默认）：定时拉取会话消息，**不需要订阅事件**。由于未订阅「接收消息」事件时飞书不允许与 bot 单聊，推荐**建一个群并把 bot 拉进去**，将群 chat_id 填入 `LARK_BOT_CHAT_ID` 与 `BOT_POLL_CHAT_IDS`（需 `im:message.group_msg` 权限）。群里只有 @bot 的消息才会收到"没看懂"的兜底回复，普通聊天不会被打扰。
- `ws`：长连接事件 + 卡片按钮交互，需在「事件与回调」订阅 `im.message.receive_v1` 与 `card.action.trigger`。

**管理员白名单**：`BOT_ADMIN_EMAILS` 填团队邮箱（启动时自动换成 open_id），或 `BOT_ADMIN_OPEN_IDS` 直接填 open_id。都为空时 bot 处于"绑定模式"，只回显发送者的 open_id，不执行任何操作。

> 不要同时运行 bot 的「跑一遍」和 `main.py` 定时模式，两个进程可能重复处理同一条素材。

```
main.py                   主入口：分步 / 一键 / 定时运行流水线，--add 人工提报素材
ops.py                    命令行快捷操作（查看、采纳、淘汰选题等）

web_scraper.py            网页正文抓取
notifier.py               选题卡片 / 结果推送到飞书

automations/              流水线引擎
  rss_fetcher.py          ① RSS 抓取
  manual_input.py         ①½ 人工提报素材
  material_processor.py   ② 素材 → 选题（AI 相关性判断）
  content_generator.py    ④ 选题 × 账号 → 初稿（按人设）

  actions.py              采纳 / 淘汰 / 审批操作
  codes.py                T# / A# 编号 ↔ 表格记录（读取「编号」列）
```

## 常见问题

**AI 调用 401**：检查 key 是否有效；若 key 来自第三方中转服务，需填对应的 `ANTHROPIC_BASE_URL` / `OPENAI_BASE_URL`。

**内容库出现奇怪的空白状态选项**：代码向单选字段写了表格中不存在的值。确认代码中的状态名与表格选项一致后，在表格里删除多余选项。

**选题采纳了但没生成初稿**：检查「适配账号」是否已填写，账号在账号矩阵中是否为「启用」。

**Windows 终端打印 emoji 报 `UnicodeEncodeError`**：先执行 `$env:PYTHONIOENCODING="utf-8"`（`ops.py` 已内置处理）。
